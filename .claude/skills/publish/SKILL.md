# LPを公開する

担当は git に詳しくない。**担当がするのは、質問に答えることだけ**。コマンドは全部こちらで打つ。

## 聞き方の決まり

- 質問は AskUserQuestion で、1回に1つだけ出す。選択肢は2つか3つ。先頭を「進める」側にする。
- 質問の前に、いま何が済んでいて、「はい」と答えると何が起きるかを1〜2行で書く。
- git の言葉は、初めて出す時に言い換えを添える（コミット＝直した内容に名前を付けて記録する／プッシュ＝GitHub に送る／プルリクエスト＝本番に入れる前の確認の場／マージ＝本番に入れる）。
- 「まだ直す」と言われたら、そこで止めて直しに戻る。同じ質問をすぐ繰り返さない。

## 手順

始める前に `git status` と `git branch --show-current` で現在地を確かめ、済んでいる段は飛ばす。main にいて変更がある時は、先に作業用ブランチを作る（`git switch -c work/YYYYMMDD-内容`）。

### 1. 直した内容を見せる

- `git diff` を読み、何をどう変えたかを、ファイル名ではなく「画面のどこがどう変わるか」で3行以内にまとめる。
- `index.html` をブラウザで開いて見せる（Mac は `open index.html`、Windows は `start index.html`）。「スマホの幅でも見てください」と一言添える。
- 画像を足した時は、`assets/` の中にあること、ファイル名が英数字と `_` `-` `.` だけであること、拡張子が小文字であることを確かめる。

### 2. 「コミットしますか」

- 選択肢: 「コミットする」「まだ直す」。
- 「コミットする」なら、`git add -A` → `git commit`。メッセージは日本語で「何を・なぜ」を1行（例: `FVの見出しを秋の募集向けに変更`）。
- コミットに入るファイルが `index.html` と `assets/` 以外を含む時は、入れてよいかを先に聞く。

### 3. 「GitHub に送って検品にかけますか」

- 選択肢: 「送る」「まだ直す」。
- 「送る」なら、`git push -u origin <ブランチ>` → プルリクエストが無ければ `gh pr create --base main --title "<コミットと同じ1行>" --body "<変えた内容を箇条書き>"`。
- `gh pr checks --watch` で検品の結果を待つ（1〜2分）。待っている間は「検品中です」と伝える。

### 4. 検品の結果

- **緑**: 「検品を通りました」と伝えて 5 へ。
- **赤**: `gh run view --log-failed` で 🛑 の行を読み、何が理由で止まったかを1行ずつ言い換えて伝える。直せるものは直して 2 に戻る。直してよいか迷うもの（noindex や計測タグを足す・消す、ファイルの種類を変える）は、勝手に直さず担当に聞く。
- `.github/` や `scripts/` を変えれば通る、という直し方はしない。

### 5. 「公開しますか」

- 聞く前に必ず伝える: 「はい」と答えると、本番（公開URL）がこの内容に置き換わること。
- 選択肢: 「公開する」「まだ出さない」。
- 「公開する」なら `gh pr merge --merge --delete-branch`。このコマンドは許可の画面が出る。担当に「画面に確認が出たら Yes を押してください」と先に伝える。

### 6. 本番を確かめる

- `gh run list --branch main --limit 1` で公開の実行を見つけ、`gh run watch <番号>` で終わるまで待つ。
- 結果を `gh run view <番号> --log` で読み、次のどれかを伝える。
  - 「✓ 本番の index.html がリポジトリと一致」「✓ assets 全て HTTP 200」が出ている → 「公開できました」と公開URLを添える。
  - 「予行演習モード」と出ている → 「本番はまだ変わっていません。このLPは公開のスイッチがまだオフです。有川さんに連絡してください」と伝える。
  - 🛑 が出ている → その行をそのまま見せ、「有川さんにこの行を送ってください」と伝える。自分で直そうとしない。
- 最後に `git switch main` → `git pull` で手元を最新にし、「次の直しを始められます」と伝える。

## 公開したものを元に戻す

1. `git log --merges -5` で、戻したい公開（マージ）を見つけ、どれを戻すかを担当に確かめる。
2. `git switch main` → `git pull` → `git switch -c work/YYYYMMDD-revert` → `git revert -m 1 <そのマージの番号>`。
3. 上の手順 3 から同じ流れで進める（送る → 検品 → 公開 → 本番を確かめる）。
4. 伝えること: 戻るのは `index.html` と、中身が変わったファイル。**足した画像は本番のサーバーから消えない**（消したい時は有川さんへ）。

## してはいけないこと

- main に直接送る。検品が赤のまま公開する。強制的に上書きする送り方をする。
- 担当に聞かずに、コミット・送信・公開のどれかを進める。
- 鍵・パスワード・個人情報が入ったファイルをコミットする（このリポジトリは誰でも見られる）。
